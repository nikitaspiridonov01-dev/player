# AirPlay Any Video — расширение Safari (macOS + iPhone/iPad)

Отправляет **любое видео с сайта на Apple TV / телевизор с AirPlay в полном качестве** — только сам плеер, а не весь экран.
Работает в Safari на Mac и на iPhone/iPad (Safari Web Extension, Manifest V3).

Зачем: при «Повторе экрана» iPhone кодирует картинку в реальном времени, качество падает, звук идёт с телефона,
а телефон нельзя заблокировать. При настоящем AirPlay-видео Safari просто передаёт телевизору **URL потока**,
и Apple TV скачивает его сам — в максимальном разрешении, с нормальным звуком, а телефон свободен.
Расширение делает этот «настоящий» режим доступным даже там, где сайт его не предлагает.

## Что умеет

| Ситуация на сайте | Что делает расширение |
|---|---|
| Обычный `<video src="…mp4">` или HLS (`.m3u8`), но сайт **запретил AirPlay** (`disableRemotePlayback`, `x-webkit-airplay="deny"`) или спрятал кнопку в своих контролах | Снимает запрет и показывает системный выбор AirPlay для **этого же плеера** |
| Плеер на **MSE** (hls.js, video.js, Shaka, JW Player, Plyr…): у `<video>` источник `blob:`, AirPlay не работает в принципе | Находит **настоящий URL потока** (HLS master-плейлист или MP4), которым пользуется плеер, запускает его в своём мини-плеере и показывает выбор AirPlay — телевизор получает прямую ссылку, качество максимальное |
| Нужна «стандартная» кнопка AirPlay | «Открыть в системном плеере» (iOS fullscreen-плеер с AirPlay) или «Открыть поток в новой вкладке» (Safari покажет поток своим плеером с AirPlay) |
| Хочется просто забрать ссылку | «Скопировать URL потока» |

Дополнительно: значок AirPlay на каждом видео (включая видео во `<iframe>`), попап со списком всех найденных видео и потоков,
синхронизация позиции (прокси-плеер стартует с того же места, где остановился плеер страницы), пауза плеера страницы на время AirPlay.

## Как это работает

1. **Поиск видео** — контент-скрипт в каждом фрейме отслеживает все `<video>` (включая открытые shadow DOM и добавленные позже).
2. **Поиск потока** — три независимых слоя:
   * собственный `src` / `currentSrc` / `<source>` элемента;
   * **Resource Timing API** — список всех URL, которые загружала страница (`.m3u8`, `.mp4`, `.mpd`, сегменты…);
   * **хук в мире страницы** (`world: "MAIN"`, Safari 16.4+): наблюдает ответы `fetch`/`XMLHttpRequest`, читает тела
     плейлистов и отличает master-плейлист (адаптивный, все качества) от media-плейлиста (одно качество), помечает
     `blob:`-URL, созданные для `MediaSource`.
   * Фоновый скрипт дополнительно «пробивает» найденные `.m3u8` и показывает максимальное разрешение (например, «до 1080p»).
3. **Классификация** (`extension/common/streams.js`): HLS master → HLS → MP4/MOV — пригодны для AirPlay;
   DASH (`.mpd`), WebM, отдельные сегменты, `blob:` — нет. Лучший кандидат подставляется в кнопку «AirPlay этого видео».
4. **Запуск** — по нажатию на значок (это важно: iOS показывает выбор устройства AirPlay только из жеста пользователя
   внутри страницы) вызывается `video.webkitShowPlaybackTargetPicker()` — у плеера страницы или у прокси-плеера с найденным URL.

## Требования

* iPhone/iPad: iOS 16.4+ (рекомендуется iOS 17+). Mac: macOS 13.3+ / Safari 16.4+.
* Для сборки — **Mac с Xcode** (15 или новее; в Xcode 26 инструмент упаковки называется `safari-web-extension-packager`,
  раньше — `safari-web-extension-converter`, скрипт сборки поддерживает оба). Расширения Safari устанавливаются только
  через приложение-обёртку, поэтому без Xcode не обойтись.
* Apple ID. Бесплатной учётной записи достаточно для установки на свой iPhone (см. ниже про 7 дней).

## Сборка и установка

```bash
git clone https://github.com/nikitaspiridonov01-dev/player.git
cd player
bash scripts/make-xcode-project.sh        # macOS + iOS; варианты: ... ios | macos
open "build/AirPlay Any Video/AirPlay Any Video.xcodeproj"
```

Скрипт генерирует Xcode-проект с двумя приложениями-обёртками (macOS и iOS); по умолчанию проект **ссылается** на папку
`extension/`, так что правки в ней сразу попадают в сборку (`COPY=1` — скопировать файлы в проект).
Имя приложения и bundle id меняются переменными `APP_NAME` и `BUNDLE_ID`.

### iPhone / iPad

1. В Xcode: выберите схему **AirPlay Any Video (iOS)**, в *Signing & Capabilities* укажите свою Team (достаточно
   бесплатного Apple ID: Xcode → Settings → Accounts) для **обоих** таргетов — приложения и расширения. Если bundle id
   занят, поменяйте `BUNDLE_ID` и пересоздайте проект.
2. Подключите iPhone кабелем (или по Wi-Fi после первого подключения), на телефоне включите *Режим разработчика*
   (Настройки → Конфиденциальность и безопасность → Режим разработчика), выберите его как устройство и нажмите **Run**.
3. При первом запуске iPhone попросит доверять разработчику: Настройки → Основные → VPN и управление устройством → ваш Apple ID → Доверять.
4. Включите расширение: **Настройки → Safari → Расширения → AirPlay Any Video → Вкл.**, ниже в «Разрешить расширению
   читать и изменять» выберите **Все веб-сайты** (или разрешайте по сайтам — Safari сам спросит при первом открытии сайта).
5. Откройте сайт с видео в Safari. На видео появится синий значок **AirPlay** → нажмите → **«AirPlay этого видео»** → выберите Apple TV.

> **Про 7 дней.** Приложение, подписанное бесплатным Apple ID, работает 7 дней, затем нужно снова нажать Run в Xcode
> (переустановка, настройки сохраняются). С платным аккаунтом разработчика (99 $/год) — год, либо TestFlight / App Store.

### Mac

Схема **AirPlay Any Video (macOS)** → Run → Safari → Настройки → Расширения → включить. Для неподписанных сборок
может понадобиться Safari → Разработка → «Разрешить неподписанные расширения» (пункт появляется после включения меню «Разработка»).

## Использование

* **Значок на видео** — главный способ (особенно на iPhone). Нажмите → панель:
  * **AirPlay этого видео** — сам выбирает путь: плеер страницы (если он играет обычный MP4/HLS) или прокси-плеер с лучшим найденным потоком.
  * Список **потоков, найденных на странице** — у каждого: тип, «до 1080p», LIVE, AES (шифрование), кнопки «AirPlay», «Открыть в новой вкладке», «Копировать».
  * **Открыть в системном плеере** — полноэкранный плеер iOS/macOS со стандартной кнопкой AirPlay.
  * **Остановить и вернуться к плееру страницы** — закрывает прокси, страница продолжает с той же позиции.
* **Попап** (кнопка расширения в адресной строке): все видео и потоки вкладки, кнопки «Открыть»/«Копировать», настройки.
  На Mac кнопка «AirPlay» в попапе обычно работает сразу; на iPhone Safari требует жест внутри страницы — попап предлагает
  «Показать значок» и подсвечивает его.
* Если поток не нашёлся: **запустите видео на несколько секунд** (плеер должен загрузить плейлист) и откройте панель снова
  или нажмите «Пересканировать».

### Настройки (в попапе)

| Настройка | По умолчанию | Описание |
|---|---|---|
| Показывать значки AirPlay на видео | вкл. | Значок на каждом подходящем видео (можно скрыть на конкретной странице кнопкой в панели) |
| Автоматически снимать запрет AirPlay | вкл. | Убирает `disableRemotePlayback` / `x-webkit-airplay="deny"` у всех плееров — стандартная кнопка AirPlay в системных контролах начинает работать |
| Ставить плеер страницы на паузу | вкл. | Чтобы звук не шёл одновременно с телефона и телевизора |
| Глубокий перехват потоков | вкл. | Хук `fetch`/`XHR` в мире страницы. Выключите, если какой-то сайт сломался; базовый перехват через Resource Timing продолжит работать |

## Что не сработает (честно)

* **DRM** (Netflix, Disney+, Apple TV+, Amazon, Кинопоиск/Okko/ivi с Widevine/FairPlay): поток зашифрован под конкретное
  устройство, ни одно расширение не передаст его на телевизор. Останется только «Повтор экрана».
* **Только DASH** (`.mpd`) без HLS/MP4-альтернативы: Safari и Apple TV не умеют DASH нативно. Расширение покажет такой
  манифест в списке серым — чтобы было понятно, почему кнопки нет.
* **YouTube**: видео и звук отдаются раздельными DASH-потоками; HLS есть только у трансляций. Для YouTube проще штатный
  AirPlay из приложения YouTube.
* **Потоки с авторизацией по cookie / Referer** (hotlink-защита): Apple TV скачивает поток сам, без cookie браузера.
  Подписанные URL с токеном в адресе (так делает большинство CDN) — работают.
* **Отдельные сегменты** (`.ts`, `.m4s`, `init.mp4`, YouTube `videoplayback?range=`) и WebM — не целый поток / не поддерживается приёмником.
* Если плеер страницы в **собственном fullscreen** на iPhone (системный плеер), значок расширения недоступен —
  выйдите из полноэкранного режима или используйте кнопку AirPlay системного плеера (после снятия запрета она работает).

## Структура проекта

```
extension/                 ← само WebExtension (его упаковывает скрипт в Xcode-проект)
  manifest.json            MV3: service worker, content scripts во всех фреймах, scripting/storage/activeTab
  background.js            регистрация MAIN-хука, агрегация состояний вкладок, пробы .m3u8, бейдж на иконке
  common/streams.js        классификация и ранжирование URL (общий модуль; покрыт юнит-тестами)
  content/content.js       поиск видео, перехват потоков, оверлей (Shadow DOM), прокси-плеер, действия AirPlay
  content/content.css      хост оверлея (внедряется манифестом — CSP страницы его не блокирует)
  content/page-hook.js     хук в мире страницы: fetch/XHR/createObjectURL(MediaSource), читает плейлисты
  popup/                   попап расширения
  _locales/{ru,en}/        локализация (Safari выбирает по языку системы)
  icons/                   иконки (генерируются scripts/make-icons.py)
scripts/make-xcode-project.sh   генерация Xcode-проекта (packager/converter)
scripts/make-icons.py           генерация PNG-иконок (Pillow)
scripts/check.mjs               синтаксис JS, валидность JSON, ссылки в манифесте
test/                      тестовая страница + Playwright e2e (Chromium) + юнит-тесты
```

## Тесты

```bash
npm install            # нужен playwright (или глобальная установка)
npm test               # check + unit + e2e
```

E2E-тест грузит расширение в Chromium и проверяет всю логику до момента вызова AirPlay API (которого в Chromium нет):
значки на видео (в т.ч. во фрейме и у добавленных позже), снятие запрета, перехват `master.m3u8` через MAIN-хук и
Resource Timing, пробу плейлиста (1080p), выбор стратегии, запуск прокси-плеера с правильным URL, попытку показать
пикер (событие `airplay-any:picker`), возврат к плееру страницы, попап и настройки.
Сам выбор устройства AirPlay проверяется только на реальном Safari (Mac или iPhone).

## Отладка на устройстве

* iPhone: Настройки → Safari → Дополнения → Веб-инспектор (вкл.). На Mac: Safari → Разработка → *имя iPhone* → страница —
  консоль контент-скрипта и страницы; там же «Web Extension Background Content» для фонового скрипта.
* Расширение не отправляет никаких данных никуда: перехваченные URL живут в памяти вкладки, пробы плейлистов идут
  напрямую на CDN сайта.
